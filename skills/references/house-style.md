# Atlas 风格基线(house style)

仅由 atlas 入口调度时使用,不是独立 skill。每个 stage 开场对齐前读一遍:第一部分是写作品味(写草稿时自检),第二部分是各话题的推荐默认(对齐时作为第一个推荐选项)。

本文件只提供**默认值**,不改变入口 `SKILL.md` 的任何纪律:仍然一问一答渐进对齐、仍然追加 reconfirm、推进仍须用户明确信号。用户在当前对话里的明确选择永远覆盖这里的默认。

来源:「Linux 文件 IO 全链路」一轮(2026-10-18 ~ 23,143 轮对话 + 七份草稿修订记录)中用户反复提出的要求,经用户确认后沉淀。参考产物:`atlas-output/Linux文件IO全链路-20261010/`。

## 一、写作品味(十二条)

1. **先立总纲再讲细节。** 任何主题先立一个稳定骨架(如 VFS → 文件系统 → 块层 → 驱动 → 硬件 五层),把用户提出的所有问题映射到骨架上,后续全部挂上去。骨架要「人类一眼能记住」,层数宁少勿多。
2. **痛点驱动、逐层生长。** Why 从最裸的起点开始(如 bootloader 直接操作硬件有多痛):一刀全切 → 加一层解决一个问题 → 暴露新问题 → 再加一层,直到骨架凑齐。
3. **约束少而根。** 叶子约束 C1~Cn 之上再提 3~5 条根约束 R1~Rk,叶子挂在根下。引用一律 `ID·短名`(如 `C7·跨块不原子`、`R5·活过断电`),从不写裸编号;短名要精确(「POSIX接口冻结」而非「POSIX 冻结」)。
4. **先陈述,再逼问。** 每个组件先给一段概念陈述 + 一张结构图或对象表,然后开「再逼问:为什么是这几样」——「没有 X 会坏在哪?X 的存在解决了没?」逐个逼出组件。节末一张「没有它会坏在哪 / 它解决了」汇总表。
5. **每一幕一个落地例子,核心转换给算例。** 例子点名具体设备、具体文件(如 NVMe SSD vs MegaRAID 阵列卡、`notes.txt`)。最关键的那一步转换要从一次真实调用出发逐步出数并对账(如 `pread(fd, buf, 6000, 10300)` 从文件偏移 → 页索引 → 文件块 → extent → 扇区 → LBA)。
6. **关键转换画图 + 函数链。** 「X 通过什么函数、什么过程变成 Y」要给单位换算链表 + 调用链 + 一张 SVG。源码钉在一个具体版本(如 Linux 6.12),行号可查;demo 用伪代码即可。
7. **节首先说结论。** 专题节开头先写「A 解决了什么、B 又解决了 A 的什么」,再用三四条短句高度总结进步点,然后才展开细节。读者应能只读节首就带走主干。
8. **类比到读者熟的域,对照要比到底。** 例:jbd2 日志 ↔ MySQL 事务 / redo / doublewrite;io_uring ↔ Windows IOCP;方法论泛化到 TCP 拥塞控制。对照逐项落表,不停在「有点像」;但范围压在读者关心的那几层。
9. **用户的猜想写进文档。** 用户给出一句话总结或问「我说得对不对,能不能加到合适的位置」时:开《你的视角》/《你的总结》小节,或直接用用户原话做小节标题;对一半就「认一半、纠一半」,并写明纠在哪。
10. **反问要有,卡住就从头讲。** 每块讲完抛一个反问;但用户答「不清楚,你说」「没看懂」时不再追问,改写一节完整解析:问题来源 → 分岔点 → 结果,并把用户最后的一句话理解记进去。
11. **范围宁全勿缺,深度堆在弱项。** 分支场景(如 fsync / O_DIRECT / mmap / socket)都写;反事实候选都写;默认详尽版。用户自述最弱的层要按「结构 / 原理 / 机制 / 策略」四面加厚。
12. **事实先标待核,收尾统一核实。** 写作时不确定的年份、版本、默认值标「待核 #n」;导出前统一核实,把核实结果表(结论 / 核实后事实 / 出处)写进文档,正文同步改。

**为什么:** 产物不只自己读,还会被切成逐集视频讲稿。结构稳定、每节自带例子与结论、用户本人的洞察有记录,三者缺一不可。用户的修订要求几乎全部落在「要例子」「要图」「先结论」「别用裸编号」四类。

**自检时机:** 每份草稿写完、每次 patch 后,至少过一遍第 3 / 4 / 5 / 7 条。

## 二、各话题推荐默认

对齐时把对应行作为第一个选项并标「推荐」,仍须用户确认;主题不同时,按第一部分的原则换算成该主题的等价选项。

| 话题 | 推荐默认 |
|---|---|
| What | 轮廓 + 边界都要;先立层次总纲;底层硬件 / 运行时基础的入门不能省;用一个场景分叉作钩子(如「数据库为什么不用 page cache」);性能优化专题留到最后 |
| Why | 痛点驱动;从最底层一层层长出来;场景叙事 + 数字;附「这些不算约束」;叶子约束之上压出 3~5 条根约束;持久性 / 一致性类约束单独展开并类比数据库事务 |
| How | 全链路按顺序讲,读者最弱的那层加厚(结构 / 原理 / 机制 / 策略);所有分支场景都写;逼问推导法(先陈述后逼问);核心转换给算例 + 图;经典算法(如电梯算法)讲透配图 |
| Origin | 技术接力打底,转折点讲人物;远古史压成短序章;转折点全要;一条重要谱系单独成节;严格一手资料并在正文附链接 |
| 分水岭 | 继续往下挖:进源码和数字;前面预留的专题也做 |
| Deep | 聚焦 3 条主线;源码钉一个版本;伪代码 demo;ns / μs 时间线只做一条主线;反事实每个机制 4~6 候选 |
| Comparison | 选一个血统不同的同类系统(如 Linux ↔ Windows NT);「比到底」但压在读者关心的几层 |
| Synthesis | 定位「自己的长期笔记」;先列全部洞察,由用户按编号挑必保条目;泛化演练选一个跨领域同构问题(如 TCP 拥塞控制);详尽版 |
| 导出 | 综合 MD + 暗色科技风 HTML |
