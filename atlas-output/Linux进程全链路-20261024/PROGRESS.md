## 约束清单(Why 阶段建立,后续阶段引用)
一刀一条,共 7 条(原 11 条叶子降为"收进来的事实",4 条根已删,见 02-why.md 压缩记录):

| # | 短名 | 约束 | 收进来的事实 | 逼出的东西 |
|---|------|------|------|-----|
| C1 | CPU快IO慢 | CPU 比设备快 10⁴ ~ 10⁷ 倍,等待是常态;一核一次只跑一条流,现场在指令边界上可存可取 | 速度差;一核一流现场可存 | 多道程序、上下文切换、中断 |
| C2 | 霸台不可预知 | 程序不会主动让台;内核猜不到它下一步要算还是要等、要快还是要多 | 程序可能永不让出;未来不可知 | 闹钟、抢占、调度算法靠历史推测、负载均衡启发式 |
| C3 | 互不信任 | 程序可能有 bug 或恶意;有些操作波及整机;程序又假定独占一套连续地址且可同时跑多份 | 程序不可信;特权波及整机;程序独占地址假设 | 地址空间 / 页表、ring 0/3、系统调用、mm_struct |
| C4 | 文件≠内存 | 程序在盘上是文件,任务要的是页表;工具链与内核不同方;内存远小于程序总量、单次只触及一小部分且有局部性;复制必须便宜 | 编译与运行分离;内存小程序大且局部 | ELF、ld.so、按需调页、共享只读页、fork + COW |
| C5 | 改流必经打断 | 内核没有自己的 CPU;ring 3 的流不会自己停;内核只能在它进内核的瞬间介入 | 隔离(C3)的直接后果 | 三扇门一扇出口、signal 出口投递、抢占靠 tick、IPI |
| C6 | 资源有限须归还 | pid / 内存 / fd 有限,无 GC;任务不能释放自己正在用的栈和账本 | 物理 + 内核设计 | exit 两段式、僵尸、wait、init 收养 |
| C7 | 核各自为政 | 核有独立 cache / 执行 / 时钟;跨核协调代价高一到两个数量级 | 硬件 | 每核就绪队列、负载均衡、IPI、亲和性 |

引用约定:一律 `ID·短名`(如 `C3·互不信任`、`C5·改流必经打断`),不写裸编号。
