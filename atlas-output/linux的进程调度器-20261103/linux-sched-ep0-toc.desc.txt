Linux 调度器大电影 — 8 条不可再分约束 C1~C8：
[C1] 只在打断点换 — 内核没有自己的 CPU，只能在 tick / 系统调用 / 中断 / 阻塞时介入；决定和真换人必须分开（标记 + 出口）
[C2] 未来不可知 — 内核猜不到任务下一步算还是等；猜意图的启发式会被骗，依据只能是可测的过去（记账）
[C3] 份额与延迟两头要 — 按权重分和醒来多久上台是两个量，一个数保不住两个；插队额度必须有界（权重 / slice / lag）
[C4] 挑人须便宜 — 每核每秒万次决定，每次不到 1 微秒，不能随任务数线性增长（红黑树 + 增量记账）
[C5] 核各自为政 — cache / TLB 各自独立，跨核贵一到两个数量级，核有远近（每核一本账 + 三种搬人）
[C6] 份额按组算 — 分配单位是容器不是线程；组要嵌套、要能封顶（cgroup 组实体 + 周期配额）
[C7] 有人要硬保证 — 公平推不出绝对时限；凌驾要配阀、准入与继承（类栈 + 95% 阀 + PI）
[C8] 核不等速且耗电 — SMT / 频率 / 大小核让算力随时变，能耗是独立目标（算力归一 + PELT）

──────────────────

一颗 CPU 面前排着十几个想跑的任务，内核每隔几微秒就要决定一次：下一个让谁上台、跑多久、放在哪颗核上。这部七集大电影只回答一个问题：内核凭什么挑下一个跑的任务，这条规则是被什么逼出来的，为什么二十年里换了三代（O(1) → CFS → EEVDF），多核和 cgroup 又把它扩展成了什么。

P0 目录：七集路线、致敬人物、八条约束与看完能做到的六件事。
P1 What：四问骨架（何时换 / 换谁 / 各多少 / 在哪换），规则只看账不看人；两个数据库口味的钩子——容器限 2 核 p99 为什么抖、给 Redis 调 nice 为什么没用。
P2 Why：从一核一队列先来先跑开始，一刀一个痛点，逼出 C1~C8。
P3 How：每核一本账与六层类栈，权重 / 虚拟时间 / lag / deadline 四个数怎么涨怎么比，标记怎么变成真换人，三种搬人，容器配额怎么落到每个线程。
P4 Origin：Ingo Molnár 与 O(1)，Con Kolivas 与 CFS 之争，Stoica / Waldspurger 的学术线，Paul Turner 的带宽控制与 PELT，Peter Zijlstra 的 EEVDF，Tejun Heo 的 sched_ext——资料一手。
P5 Deep：Linux 6.12 源码三条主线——pick_eevdf 挑人全程、唤醒选核与周期均衡、cgroup 带宽 throttle，各在哪一行；一个能在 macOS 上跑的 EEVDF 模拟器核对手算。
P6 Comparison：Windows NT 的 32 级优先级 + 提升 对 Linux 的账 + lag，按四问逐问比；SQLOS 为什么能绕开两条约束。
P7 Synthesis：五元组 14 行过筛、必保 11 条洞察、三个同构（块层 IO 调度器 / Go GMP / fq_codel）、五步法，再拿 MySQL 线程池走一遍，最后押一个十年赌注。

人物：Ingo Molnár、Con Kolivas、Ion Stoica、Carl Waldspurger、Paul Turner、Peter Zijlstra、Tejun Heo、Linus Torvalds、Dave Cutler。
适合人群：想把 nice、EEVDF、负载均衡、cgroup CPU 限额连成一条线的 Linux 开发者；被容器 CPU throttling 抖动困扰的数据库 / 后端工程师；准备操作系统面试的同学；想学会用约束推导系统设计的技术读者。
源码基准：Linux 6.12（x86-64）；所有源码片段标注文件与行号，可自行核对。
