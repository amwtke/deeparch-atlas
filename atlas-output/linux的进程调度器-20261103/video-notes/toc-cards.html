CONSTRAINTS · 八条不可再分约束
整部电影只向这八条收敛
第 2 集建立 · 后五集引用
C1
只在打断点换
内核没有自己的 CPU,只能在 tick / 系统调用 / 中断 / 阻塞时介入
C2
未来不可知
猜意图的启发式会被骗,依据只能是可测的过去
C3
份额与延迟两头要
按权重分和醒来多久上台是两个量,插队额度须有界
C4
挑人须便宜
每秒万次决定,每次不到 1 μs,不随任务数线性增长
C5
核各自为政
cache / TLB 各自独立,跨核贵一到两个数量级,核有远近
C6
份额按组算
分配单位是容器不是线程;组要嵌套、要能封顶
C7
有人要硬保证
公平推不出绝对时限;凌驾要配阀、准入与继承
C8
核不等速且耗电
SMT / 频率 / 大小核让算力随时变;能耗是独立目标
口播一律"C 几 · 短名";画面出现编号时请对照本卡
TAKEAWAYS · 看完你能做到
六件事,带着走
适合:Linux 开发者 · 数据库 / 后端工程师
01
说清挑人规则
在有资格的任务里挑截止期最早的;权重管份额,slice 管延迟,lag 管资格
02
把三个旋钮分开
nice 不治延迟,taskset 绑一边更糟,cpu.max 抖在周期 —— 份额、延迟、位置各一个旋钮
03
读懂三代换代
2002 为了便宜和多核,2007 为了不猜意图,2023 为了把份额和延迟拆开
04
顺着 6.12 源码走
pick_eevdf、place_entity、sched_balance_rq、throttle_cfs_rq,每个决定落在哪一行
05
分清必然与血统
拿 Windows NT 对照:有界插队是约束,猜不猜意图是血统
06
把五步法搬走
识别约束 → 列候选 → 算代价 → 看现实 → 证局部最优;用 MySQL 线程池演练一遍
