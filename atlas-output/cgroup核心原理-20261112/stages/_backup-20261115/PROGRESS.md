| # | 约束 | 来源 | 不可再分性 |
|---|------|------|-----------|
| C1 | 业务是一组进程:管的单位必须是「组」,管的是合计 | 进程模型(fork)+ 应用自己决定开几个进程 | 开几个进程是应用的自由,内核无法预知也不能禁止 |
| C2 | 上限要是绝对数:不随对手多少、不随自己进程数变化 | 多个业务同机时相互的承诺 | 相对权重只能回答「谁多」,回答不了「最多多少」 |
| C3 | 被管者不可信:组籍和上限由内核强制、管理员掌握 | 被限制的程序不是管理员写的 | 只要边界能被进程自己改,就不存在边界 |
| C4 | 账要记在物理消耗上:物理页、真实 CPU 时间、真实 IO | 硬件:稀缺的是物理资源 | 地址空间等预订量不稀缺;页缓存等消耗不挂在任何进程名下 |
| C5 | 内存不可压缩:超了只能回收或杀,杀的范围必须有边界 | 资源的物理性质 | CPU 时间每个周期都有新的,物理页占了不还就没有 |
| C6 | 共用一个内核:隔离不能靠每人一套内核;记账在最热的路径上,必须便宜 | 成本 | 预留出去的资源无法互借;要互借就必须同处一个内核 |
| C7 | 限额要能层层转包:组套组,父组的上限约束整棵子树 | 资源归属的层级(机器 → 平台 → 租户 → 容器) | 上级管不了也不该管下级内部怎么分,但必须管住合计 |
| C8 | 一笔开销跨多种资源:所有资源必须共用同一套分组 | 内核实现的事实:写文件先占内存、后由内核线程写盘 | 占内存的人和发 IO 的人不是同一个执行者,两边必须能查到对方的组 |
